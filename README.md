# Skill Tester

One chatbot brief, one model, different design skills. Explore live AI-generated React/Tailwind interfaces side by side.

**[Open the comparison site](https://christophbuehler.github.io/skill-tester/)**

## Local development

Requires Node 22+, pnpm 10.17.1, and Chromium for Playwright.

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm build
pnpm dev
```

Open `/skill-tester/`. The build materializes the catalog, runs, and evidence. `pnpm exec vite preview` serves the complete built comparison including embedded variants; `pnpm dev` is for the gallery shell.

```sh
pnpm test        # mock behavior and runner invariants
pnpm typecheck
pnpm build
pnpm test:e2e
pnpm validate    # all of the above
```

## Generate a variant

Use the repository's `generate-ui-comparison` skill, or the local runner directly. Generation requires authenticated Codex CLI 0.153.4+ and APM 0.25.0+; it uses your local Codex account. It does not require a hosted application backend. The initial benchmark fixes `gpt-6-astra` with medium reasoning in `benchmark/config.json`.

```sh
pnpm generate frontend-design --preflight
pnpm generate frontend-design
pnpm validate
```

A profile is a named list of skills. An empty list is the baseline; one skill is the default. To combine skills into **one** generated interface:

```sh
pnpm run profile add design-craft-ux frontend-design impeccable ui-ux-pro-max
cd profiles/design-craft-ux
apm install
cd ../..
pnpm generate design-craft-ux --preflight
pnpm generate design-craft-ux
```

For four skills, register the fourth in `profiles/registry.json` with its repository, skill subdirectory, full commit SHA, display name, and license, then pass all four IDs to `profile add`. For a skill update, add a new registry ID and profile rather than changing an existing revision. The runner rejects registry/manifest/lockfile mismatches. Every selected skill is explicitly loaded; references are available on demand. Profile order is preserved in the record. The brief takes precedence over conflicting guidance; equally ranked skill conflicts are resolved by the generating model and recorded in its design note.

Generate profiles sequentially: local acceptance checks use port 4183. Do not run generation while another process owns that port. Run IDs are immutable. A failed run remains in the gallery and is not silently replaced. A new attempt always has a new ID.

## Methodology

This is a practical showcase, not a statistically reliable ranking. One sample cannot separate skill influence from model sampling variation. Impeccable also shares some lineage with Anthropic's design guidance. Combined skills change both instruction content and length.

Within a benchmark version, every run starts with the same task prompt, React/Tailwind starter, dependency lockfile, headless mock agent, fixed content, and tests. Only the skill profile changes. The presentation is generated by Codex, not manually themed copies. The runner creates a temporary Git repository, installs that profile through APM, and launches an ephemeral Codex session. It uses a temporary Codex configuration with access to the existing authentication file, disables memory/plugins and unrelated skills, then inspects the model-visible prompt to verify the skill inventory. Temporary credentials are never copied into output and are removed when the runner exits.

The runner records successful skill-entrypoint read evidence, exact upstream revisions, input hashes, model/settings, CLI/APM versions, elapsed time, reported token usage, validation results, and repair count. APM dependencies and installed references stay local; public metadata links to upstream source and licenses. The coordinator's design instructions do not enter the generated workspace.

Folio v2 gives each profile a 30-minute implementation session, one 10-minute visual refinement session with identical browser capture coverage, and at most one 10-minute repair session total based on objective type/build/browser failures. These are time limits, not equal token budgets. Browser accessibility findings are reported separately from functional acceptance. Raw session logs remain in ignored `.local/`; they are not published. Changing benchmark inputs requires a new benchmark ID and new runs.

### Generation environment

Generating sessions use a workspace-write sandbox with external network access disabled. Sandbox restrictions block browser launch and local server ports. In v2 the independent runner captures eight images across desktop, intermediate, and mobile welcome/research views plus mobile attachment/activity states, tests cancellation and reduced-motion rendering, and passes those images and observations directly into a fresh refinement session using the same profile. It captures the same states again after refinement. These are real browser snapshots and scripted interactions, not interactive browser control by the generating model; motion quality still needs human review. V1 had external acceptance capture only, without visual feedback to the model. Builds can use Vite's runner config loader when its default temporary-file path is not writable. Impeccable's context launcher used its documented reference-reading fallback. These results compare the skills within this constrained environment, not every tool-assisted capability they might provide in an unrestricted setup.

### What is fixed

Folio is a fictional research chatbot with conversation switching, Markdown and code, simulated streaming/tool activity, stop/retry, and local attachment metadata. The shared hook owns behavior; each generated interface owns presentation. Attachments are never uploaded or persisted. PDFs are not parsed, and responses are fixtures, not real document analysis. Reloading resets the demo.

The comparison shell uses separate iframes for CSS and state isolation. Desktop previews render at 1440×1000 and mobile at 390×844, scaled to fit their panels; standalone links offer full-size interaction. Scenario changes and reset apply to both panels. Hash URLs preserve selected runs, viewport, and scenario.

### Repository map

- `benchmark/`: fixed brief, contract, and run settings.
- `packages/mock-agent/`: headless state and deterministic fixtures.
- `starter/`: identical unstyled presentation starting point.
- `profiles/`: registry, per-profile manifests and APM lockfiles.
- `scripts/`: registration, isolation, generation, validation, and build.
- `runs/<id>/`: generated source, sanitized metadata, and browser screenshots.
- `src/`: comparison website; generated catalog is rebuilt from run records.
- `.agents/skills/generate-ui-comparison/`: natural-language workflow.

## Custom skill: Modern Interface Craft

[`skills/modern-interface-craft/SKILL.md`](skills/modern-interface-craft/SKILL.md)
contains an original design skill created using Anthropic's Skill Creator workflow.
It emphasizes clean contemporary composition, useful responsive behavior, coherent
visual identity, purposeful motion, and complete microinteraction states. It does
not impose a palette, component library, font, or animation dependency.

The [research notes](skills/modern-interface-craft/references/research.md) and
[source audit](skills/modern-interface-craft/references/source-audit.json) record
all 555 external resources and designer URLs discovered across Designeer's pages.
Coverage includes 454 readable pages, 64 limited shells, and 37 unavailable or
blocked responses; it is not a claim of 555 rendered usability reviews.

Use the pinned single-skill profile:

```sh
pnpm generate modern-interface-craft --preflight
pnpm generate modern-interface-craft
```

Or explicitly combine it with the existing three skills in one new variant:

```sh
pnpm run profile add all-four frontend-design impeccable ui-ux-pro-max modern-interface-craft
(cd profiles/all-four && apm install)
pnpm generate all-four --preflight
pnpm generate all-four
```

Registering a profile does not generate a result or change existing runs. The
custom skill lives outside `.agents/skills` so it is available only when selected
by a profile; it cannot silently influence baseline or other skill runs. When
editing it, commit and push the new source first, then register a new profile
pinned to that exact revision. Preserve old profile pins and immutable results.

See the [initial authoring evaluation](docs/modern-interface-craft-evaluation.md)
for paired prototype checks, contrast findings, and evaluation limitations.

## Folio v2

The current benchmark expresses capabilities rather than prescribing sidebar, card, or attachment presentation. Conversation navigation may be disclosed at any width; suggestions are optional. V1 prompts/configuration remain in `benchmark/versions/folio-v1`, with existing runs and profile pins unchanged. The gallery labels benchmark versions and warns about comparing different inputs.

```sh
pnpm generate baseline-v2 --preflight
pnpm generate baseline-v2
pnpm generate modern-interface-craft-v2 --preflight
pnpm generate modern-interface-craft-v2
```

The updated skill favors minimal product composition, concrete copy, contextual controls, and continuity between meaningful states. Its aesthetic guidance appears only in that skill profile. Both profiles receive identical neutral implementation/refinement prompts and budgets. New metadata records the exact prompts, refinement count, browser observations, and before/after captures. One pair is a showcase, not evidence of a reliable skill ranking. Functional success and accessibility findings are separate from a human design assessment.
