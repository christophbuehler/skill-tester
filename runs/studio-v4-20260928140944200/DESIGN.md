# Folio — design decisions

## Before implementation

Three product approaches considered in this session:

1. **Research dashboard.** Persistent navigation, recent conversation cards, and a separate input panel. It makes history obvious, but gives the two supplied threads and empty project structure disproportionate space. Modern Interface Craft, “One work surface,” explicitly favors contextual history and unboxed work; this is a good fit for the small, conversation-based API.
2. **Document desk.** A split document viewer with a narrow conversation alongside it. This would be useful for verifying source material, but the hook provides attachment metadata, not document content or citations. A viewer would imply capabilities this product does not have. Rejected on the contract and Apple Design §16 “Purpose.”
3. **Reading workspace — selected.** A lightly warm, open canvas with one shared reading edge, an expressive compact input, and a small conversation disclosure. Actual recent threads support returning to work on the welcome view. Populated views give the majority of space to the question and Markdown answer. This is a design judgment, not a measured usability result.

The principal content and composer align in a 760px maximum column. A short, left-aligned opening question leads directly into the input. The composer has a 64px minimum silhouette, 32px outer corners, and 44px circular end controls inset 10px from its outer edge. Conversation history originates at the current-thread trigger in the top navigation. The important object transition is an attachment: its hook ID, name, and size survive from pending files into submitted context; removal changes state immediately and remaining files reflow locally.

## Verification and refinement record

### Implementation session

The complete presentation is implemented in `src/App.tsx` and `src/styles.css`. The supplied hook, fixtures, main entrypoint, dependencies, configuration, and tests are unchanged. No backend, external asset, or network request was added.

Decisions made during source review:

- The input repositions directly into its dock on the first send, with the same DOM node and draft state. A long animated trip from welcome to bottom would obscure the first answer and is not a modest relocation; Apple Design's purpose and reduced-motion principles favor immediate placement here. The history disclosure and local attachment reflow still use springs.
- Tool activity uses a stable, inspectable summary instead of automatically expanding and collapsing during streaming. All step labels remain in the DOM and the reader decides when to reveal them. This avoids automatic movement above the answer.
- Pending attachment corners are 18px at a 14px inset from the 32px composer. Their remove controls have 10px corners at an 8px inset. Document glyphs are unboxed to avoid a second curve with unequal insets. The removal animation makes exiting controls inert immediately.
- Kept mobile guidance and privacy text at 12px instead of the initially authored 10px. Accessibility and Modern Interface Craft's readable secondary labels favor wrapping over shrinking. The welcome placeholder was shortened to avoid requiring a taller empty input on narrow screens.
- Static contrast calculation caught the initial placeholder at 4.28:1 on the input. It was darkened before delivery. The input outline now uses the 3.15:1-on-white boundary token. Foreground/canvas is 13.65:1, muted/canvas 5.27:1, muted/context 4.89:1, accent/accent-soft 6.02:1, action text/action 11.67:1, error text/error surface 6.47:1, focus/surface 5.27:1. These are token calculations, not a rendered accessibility audit.

Verified with `pnpm typecheck` and `pnpm build --configLoader runner`. Build succeeds; Vite reports a non-blocking bundle-size advisory, and Node reports a deprecation from the supplied runner. Static inspection confirms exactly one hook call, semantic token usage, named contract controls, native Markdown rendering, IME-aware Enter handling, and direct hook operations for send/stop/retry/navigation/files.

Browser screenshots, keyboard tests, clipboard permission behavior, scrolling with a mobile software keyboard, animation contact sheets, and rendered accessibility results have **not** been reviewed in this session. The brief assigns browser capture outside the sandbox to the external runner; no browser restriction was bypassed. The two browser-informed refinement sessions remain available when that evidence is supplied. No claim of WCAG conformance or causal usability improvement is made.

### Objective repair: mobile horizontal overflow

The supplied runner report passes four behavior tests and fails the document-width assertion in the responsive test. Its desktop capture exists, and its failure snapshot shows the mobile composer guidance. Source inspection identifies an implicit `auto` grid column on `.app-shell`, allowing the workspace's intrinsic Markdown width to expand the page. The existing mobile table has a 420px minimum width and its own focusable horizontal scrolling region.

Changed only the shell's column sizing to `minmax(0, 1fr)` in `src/styles.css`, so the reading column can fit the viewport while tables and code retain local scrolling. Considered clipping horizontal overflow at the page boundary; rejected because it could hide content and focus indicators without correcting track sizing. Modern Interface Craft's `references/light-workspace.md`, “Adapt to real input methods,” supports fitting the work without shrinking reading text or touch targets. Accessibility's “Focus visible” supports preserving the existing focusable table region. Apple Design's flexibility principle is consistent with this fix; Beautiful Shadows and Nested Geometry required no new decisions, and existing materials, radii, insets, and motion remain as authored. This is a targeted layout repair, not a new design direction or a usability claim.

Repair verification: `pnpm typecheck` and `pnpm build --configLoader runner` pass. The build retains the existing bundle-size advisory and supplied-runner deprecation warning. `pnpm test:e2e` was attempted but could not start its preview server: Vite received `EPERM` while writing its temporary bundled configuration under `node_modules/.vite-temp`. No browser assertion ran in this repair session. No sandbox workaround or protected-file edit was attempted; the external runner still needs to confirm the repaired responsive assertion.

### Browser-informed refinement 1

Reviewed all five selected skill entrypoints again, the two Modern Interface Craft implementation references, the presentation contract, source, and the ten supplied screenshot/contact-sheet images. The following three weaknesses were identified **before changing source**:

1. **The mobile reading area gives too much space to supporting UI.** In `mobile-research.png`, the answer's table reaches the dock after only its first row; `mobile-activity.png` has the same restricted reading window. A large header, widely separated turn labels, and two lines of composer instructions compete with the result. The dock occupies normal layout space rather than covering content, but the allocation is still poor. Desktop's generous welcome space works; shrinking every screen indiscriminately was considered and rejected.
2. **Structured answers are harder to use than prose.** In `mobile-research.png` and the final `interaction-mobile.png` samples, the Owner column sits outside the visible table and the code continues horizontally. The report identifies a serious `scrollable-region-focusable` failure on `pre`. Hiding columns, turning the table into fixture-specific cards, or wrapping code arbitrarily would lose either comparison or code formatting. Let ordinary tables wrap their cells within the available width and make the code region explicitly keyboard-scrollable.
3. **Returning to work is treated as starting to type.** Both recent-work and history selections currently call `focusComposer()`, despite opening an existing answer. That is established by source, not proof of an on-device keyboard opening in the screenshots. The strong rectangular textarea outline visible in `mobile-activity.png` and both interaction sheets also introduces a competing shape inside the capsule. Preserve one mounted input, direct placement, and its outer geometry, but distinguish reading focus from new-chat focus and put writing focus on the whole instrument.

### Browser-informed refinement 2

Reread the five selected skill entrypoints, Modern Interface Craft's two implementation references, the contract, capabilities, ledger, and presentation source. Reviewed the ten supplied images from `review-round-1`. Before changing presentation source, identified these three consequential weaknesses:

Source confirms that the existing floating “Latest response” control is only initialized by a scroll event. There is no initial continuation affordance. The table now fits all three columns, so making the content smaller again would address the wrong problem.
2. **Reading continuity is incomplete.** Source resets `scrollTop` to zero on every thread change and keeps automatic following enabled within 100px of the bottom. The source labels the answer “Writing response” even during preparation. The activity card consumes space needed by the answer and repeats status already conveyed nearby.

### Curated coordinator follow-up — additional review

This scoped review is separate from the benchmark refinements above. Reread all five selected skill entrypoints, Modern Interface Craft's two implementation references, source, contract, capabilities, and inherited ledger. Before editing, identified three priorities: outer scrolling undermines the stable reading dock; arbitrary table word breaks hinder comparison; the final attachment disappears without completing its exit. The uppercase history heading is a smaller copy inconsistency. The supplied welcome/attachment views support preserving the compact instrument, aligned reading column, and measured curves.

1. **Contain announcements, retain reading behavior.** Previously the copy-status span used absolute `sr-only` positioning without a local containing block or explicit origin. The coordinator reports approximately 1154px document height around an 844px shell. Accessibility's “Visually hidden class,” “Live regions,” and “Focus not obscured,” plus Modern Interface Craft's “Give real objects continuity,” favor local announcements without moving reading focus. In `src/App.tsx`, `CopyResponse` now supplies its own positioned wrapper. In `src/styles.css`, `.sr-only` has explicit top/left coordinates; the shell, transcript, thread, and composer guidance establish appropriate local origins. Mobile hidden keyboard guidance also has explicit coordinates. Considered root overflow clipping; rejected because it masks the cause and can conceal focus. The transcript remains the intentional reading scroller, with existing continuation, saved position, and focus behavior retained.

2. **Let intact words determine column allocation.** Previously tables inherited Markdown's `overflow-wrap: anywhere`, allowing even short identifiers to split. Instead of fixture-specific widths or smaller type, `.markdown table` now explicitly uses automatic layout and normal word wrapping, while headers stay on one line (`src/styles.css`). Intrinsic word widths guide allocation; unusually wide content retains the named, keyboard-focusable local scrolling region and native table semantics. This applies Modern Interface Craft's “Adapt to real input methods” instruction to reduce peripheral demands before shrinking reading text, and Accessibility's “Keyboard accessible.” Fixture content is untouched.

3. **Keep attachment exits alive.** Previously the conditional list removed `AnimatePresence` when its last item disappeared. The new persistent `PendingFiles` component in `src/App.tsx` measures the band and animates its viewport height; the presence manager and stable hook IDs remain mounted. `src/styles.css` moves scrolling/clipping to that animated viewport so the inner grid cannot prematurely clip the exiting item. Removal still calls the hook immediately, makes exiting controls inert/hidden, and focuses the persistent textarea. Modern Interface Craft's “File list reflow” and Apple Design §§3/4/14 support interruptible, no-bounce collapse with immediate reduced-motion placement. Apple's §11 transform-only advice yields here to bounded height animation: actual layout must collapse without scaling filenames. No animation gates the action.

4. **Finish the quiet hierarchy.** `ConversationNavigation` now says “Conversations,” without uppercase tracking. Modern Interface Craft's “One work surface” and Apple Design §16 Simplicity support this restrained correction. No headings or badges were added.

Nested Geometry confirms the existing 32px/22px composer relationship and derived 18px/10px file corners; focus inset space is retained. Beautiful Shadows confirms existing elevation and causes no new shadow decision. Its literal-color utilities still yield to centralized semantic tokens.
